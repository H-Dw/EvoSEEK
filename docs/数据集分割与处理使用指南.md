# 数据集分割与处理使用指南

本文说明如何把原始蛋白质 fitness 数据规范化，并一次生成五折的 `AL96 closed-loop`、`FLIP-compatible static OOD` 或 `Mutation-identity OOD` 数据包。

## 1. 环境准备

在项目根目录执行。推荐先安装项目及开发依赖：

```powershell
cd D:\fitness-agents
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

如果还没有 `.venv`：

```powershell
cd D:\fitness-agents
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

下文均使用 Windows PowerShell 命令。Linux/macOS 可把 `.\.venv\Scripts\python.exe` 替换为 `.venv/bin/python`。

## 2. 准备输入数据

### 2.1 GB1

默认配置文件为：

```text
configs/data/splits/gb1.yaml
```

它默认读取：

```text
data/raw/flip/gb1/four_mutations_full_data.csv
```

如果原始文件尚未下载，先使用项目已有的下载脚本，再确认 CSV 至少包含：

- `Variants`：四位点序列，如 `VDGV`；
- `HD`：原始 Hamming depth，仅用于来源检查，canonical depth 会根据 WT 重新计算；
- `Fitness`：结合 fitness；
- `sequence`：模型使用的序列表示。

GB1 的 WT、位点和来源列均由 YAML 显式定义，分割代码不会从 target 或全体样本中猜测 WT。

### 2.2 其他单组分或多组分数据集

复制示例配置：

```powershell
Copy-Item configs/data/splits/flip2_pdz3.example.yaml `
  configs/data/splits/flip2_pdz3.yaml
```

然后修改：

- `source`、`sequence_column` 和 `target_column`；
- 每个 component 的经过验证的 `reference`；
- 如果需要，设置真实残基编号 `positions`；
- 多组分数据设置 `component_separator`，例如 PDZ3 的 `PDZ3:CRIPT` 表示。

若发布文件以空侧表示未突变 component（例如 `:CRIPT_variant`），适配器会用 YAML 中该侧的 reference 补齐，而不会从其他数据行推断。

不要保留示例中的 `REPLACE_WITH_VERIFIED_*` 占位符。代码故意不通过多数票推断 reference，以避免跨 split 信息污染以及错误的 mutation identity。

## 3. 一次生成五折

构建命令总是输出 `fold_00` 至 `fold_04`；训练或评测时再选择具体 fold。

### 3.1 AL96 closed-loop

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/gb1.yaml `
  --strategy al96_closed_loop `
  --n-folds 5 `
  --seed 20260815 `
  --protocol-version GB1-AL96-5CV-v1 `
  --output-root data/processed/splits
```

GB1 默认参数为：

```text
initial_budget = 96
test_depth_min = 3
validation_size = 384
validation_strata = mutation_count,backbone_id
```

初始集应严格得到 WT 1 条、全部单点 76 条和标签盲选择的双点 19 条。五个 outer final test 对全部 HD3/HD4 变体进行互斥且完整的分片。

调整通用数据集参数的示例：

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/my_dataset.yaml `
  --strategy al96_closed_loop `
  --initial-budget 128 `
  --test-depth-min 2 `
  --validation-size 256 `
  --validation-strata mutation_count,backbone_id `
  --protocol-version my-al-v1
```

### 3.2 FLIP-compatible static OOD

下面构建 `two-vs-rest`：HD≤2 是训练域，HD>2 是五折共同的固定 OOD test；五折只轮换训练域中的 validation。

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/gb1.yaml `
  --strategy flip_static_ood `
  --ood-rule two_vs_rest `
  --population full `
  --n-folds 5 `
  --protocol-version FLIP-two-vs-rest-5CV-v1
```

可选规则：

```text
one_vs_rest
two_vs_rest
three_vs_rest
low_vs_high
```

`low_vs_high` 和 `population=flip_keep` 需要先读取真实 fitness 才能决定成员资格。必须显式确认：

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/gb1.yaml `
  --strategy flip_static_ood `
  --ood-rule low_vs_high `
  --allow-label-dependent-membership `
  --protocol-version FLIP-low-vs-high-v1
```

这类输出只能用于静态回顾性基准，manifest 会标记为 label-conditioned，不能作为标签盲 closed-loop 候选池。

### 3.3 Mutation-identity OOD

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/gb1.yaml `
  --strategy mutation_identity_ood `
  --mutation-row-policy contains_unseen `
  --mixed-policy quarantine `
  --n-folds 5 `
  --protocol-version Mutation-OOD-5CV-v1
```

原子 mutation identity 定义为：

```text
(backbone_id, component_id, position, wild_type_residue, mutant_residue)
```

一个变体如果同时包含本折 validation-held-out 和 test-held-out identity，会进入 `quarantine`，不会被“test 优先”规则强行并入测试集。

更严格但数据利用率更低的模式：

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/gb1.yaml `
  --strategy mutation_identity_ood `
  --mutation-row-policy pure_group_only `
  --protocol-version Mutation-OOD-pure-v1
```

### 3.4 一次生成全部三种策略

```powershell
.\.venv\Scripts\python.exe scripts/data/build_splits.py `
  --dataset-spec configs/data/splits/gb1.yaml `
  --strategy all `
  --n-folds 5 `
  --seed 20260815 `
  --protocol-version v1
```

每种策略都会独立生成五个 fold。

## 4. 输出结构

默认输出位置为：

```text
data/processed/splits/<dataset>/<strategy>/<protocol_version>/
```

主要文件：

```text
manifest.public.json
audit_summary.json
fold_00/
  fold_manifest.json
  agent/
    initial_or_train_observed.csv.gz
    candidate_pool.csv.gz
  controller/
    benchmark_validation.csv.gz
  oracle/
    queryable_labels.csv.gz
  evaluator/
    final_test_inputs.csv.gz
    final_test_labels.csv.gz
  quarantine/
    excluded_variants.csv.gz
  compat/
    flip.csv.gz
```

`compat/flip.csv.gz` 只由 `flip_static_ood` 生成。它使用 FLIP 的 `sequence,target,set,validation` 格式，但不应作为 agent runtime 的安全输入。

所有 CSV gzip 文件使用固定压缩时间戳，以保证相同代码、输入和配置能够产生稳定字节。manifest 记录 source、配置、代码、assignment 和输出文件哈希。已有目录只有在 source/config/code 哈希一致且所有文件通过校验时才可直接复用；否则必须更换 `--protocol-version`，不会静默覆盖。

## 6. 按权限读取数据

不要在同一个训练进程里读取整个 fold。使用 manifest-driven loader 只打开当前角色需要的文件：

```python
from fitness_agents.data import load_fold_bundle

root = "data/processed/splits/GB1/al96_closed_loop/GB1-AL96-5CV-v1"

agent_view = load_fold_bundle(root, fold_index=0, consumer_role="agent")
observed = agent_view.observed       # 有标签的已完成实验
candidates = agent_view.candidates  # 只有序列/突变信息，没有 target

controller_view = load_fold_bundle(root, 0, "controller")
validation = controller_view.validation

evaluator_view = load_fold_bundle(root, 0, "evaluator")
final_inputs = evaluator_view.final_inputs
final_labels = evaluator_view.final_labels
```

`agent` 视图不会加载 validation、oracle 或 final-test 标签；`oracle` 视图不会加载 final-test 标签；`evaluator` 视图不会加载 queryable labels。文件读取时会重新校验 manifest 中的 SHA-256。

闭环 oracle 示例：

```python
from fitness_agents.loop import CsvOracleBackend

fold_root = (
    "data/processed/splits/GB1/al96_closed_loop/"
    "GB1-AL96-5CV-v1/fold_00"
)
oracle = CsvOracleBackend.from_fold(fold_root, query_budget=480)

run_id = oracle.submit(["sha256:..."], round_id=1)
observations = oracle.collect(run_id)

# 所有实验收集完成后才能打开一次；打开后不可继续查询。
final_observations = oracle.open_final_test()
```

## 7. 五折训练与主动学习注意事项

### 7.1 将 manifest/fold 直接接入标准 campaign

正式闭环配置已提供：

```text
configs/task/gb1_binding_al96.yaml
configs/experiments/knowledge_agent_al96.yaml
```

任务配置不再填写旧的 `public_data_path` 和 `oracle_data_path`，而是直接指定 split manifest 根目录和 fold：

```yaml
task_id: gb1_binding_al96
protein_id: GB1
assay_id: GB1_IgG_binding_Wu2016
wild_type_sites: VDGV
mutable_positions: [39, 40, 41, 54]
objective: maximize
split_root: data/processed/splits/GB1/al96_closed_loop/GB1-AL96-5CV-v1
fold_index: 0
expected_split_strategy: al96_closed_loop
expected_protocol_version: GB1-AL96-5CV-v1
# 正式冻结 benchmark 时还可填写：
# expected_manifest_sha256: <manifest.public.json 的 SHA-256>
# expected_assignment_sha256: <当前 fold 的 assignment_sha256>
```

先按第 3.1 节生成完全相同 `protocol_version` 的数据包，然后运行标准 campaign：

```powershell
.\.venv\Scripts\python.exe -m fitness_agents.cli `
  configs/experiments/knowledge_agent_al96.yaml
```

运行其他 fold 不需要复制五份 experiment YAML：

```powershell
.\.venv\Scripts\python.exe -m fitness_agents.cli `
  configs/experiments/knowledge_agent_al96.yaml `
  --fold-index 3 `
  --seed 14
```

`--fold-index` 只选择已经生成的 fold，不会重新拆分数据。正式五折实验应分别运行 `0..4`，并为每一折使用独立进程和状态目录。

标准 runner 在 manifest 模式下会执行以下检查：

- 任务配置中的 expected strategy/protocol 与 manifest 一致；
- fold manifest 及其能力文件 SHA-256 一致；
- 初始集和候选池只从 agent view 加载；
- oracle 由当前 `fold_XX/oracle/queryable_labels.csv.gz` 创建，并限制总查询预算；
- 固定 benchmark validation 不进入逐轮 predictor fitting；
- final-test inputs 延迟到闭环结束后加载；
- final inputs 与 oracle final labels 的 variant ID 必须完全一致；
- `config.json` 和 `summary.json` 记录 strategy、protocol、fold、manifest hash 与 assignment hash。

旧 task 配置仍可使用 `public_data_path + oracle_data_path`，但两种数据源模式严格互斥；同一 task YAML 同时配置两者会直接报错，避免 runner 静默选择错误数据。

### 7.2 闭环使用边界

- `fold_00` 至 `fold_04` 是五次独立实验，不是五轮主动学习；
- 每折必须重置模型权重、优化器、随机数、replay buffer、LLM memory、KG 写回和缓存；
- AL 每轮只能使用初始标签和此前轮次实际查询返回的标签；
- 固定 benchmark validation 不进入 acquisition loop；
- final test 只在模型和策略冻结后由 evaluator 打开一次；
- FLIP static OOD 默认不能查询固定 OOD test；
- Mutation-identity OOD 一旦查询 test identity，就不能再声称它是 unseen identity。

## 8. 常见报错

### `ModuleNotFoundError: fitness_agents`

使用项目虚拟环境并执行 editable install：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

### 输出目录已存在但 manifest 不同

不要删除或覆盖正式数据包。提高协议版本：

```text
--protocol-version v2
```

### mutation identity 数量不足以支持五折

某个 component/position 必须至少拥有五个可分配的 mutation identities。代码会列出不足的位置，不会退化为容易泄露的 row-wise KFold。应修正 reference/position 配置、增加合法数据，或仅在开发实验中明确降低 `--n-folds`。

### label-dependent 策略被拒绝

只有明确需要复现 `low_vs_high` 或 `flip_keep` 时才添加：

```text
--allow-label-dependent-membership
```

不要把这类结果解释为标签盲闭环发现性能。

`scripts/data/prepare_gb1.py` 和旧的 `gb1_*_public.csv`/`gb1_*_oracle.csv` 暂时保留用于已有 demo 与回归测试。新的正式五折实验应使用 `scripts/data/build_splits.py` 和 manifest-driven 输出；不要把旧单次随机 split 与 `GB1-AL96-5CV` 混合汇总。
