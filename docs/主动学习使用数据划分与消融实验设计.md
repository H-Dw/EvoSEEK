# 主动学习如何使用五折数据划分，以及消融实验的公平比较设计

## 1. 文档目的

本文说明主动学习（active learning, AL）及其消融实验应如何使用以下三类五折数据划分：

1. `AL96 closed-loop`：模拟从 96 条已完成实验出发、逐轮提出并测量候选突变体的闭环定向进化；
2. `FLIP-compatible static OOD`：评估从低阶突变或低 fitness 区域向固定 OOD 区域的静态外推能力；
3. `Mutation-identity OOD`：评估模型面对训练期间从未出现过的原子突变身份时的泛化能力。

本文不讨论分割代码本身的模块实现；实现方案见《数据集分割代码模块改进 PLAN》。这里专门规定数据的使用权限、主动学习与非主动学习基线之间的差异，以及公平消融所需的实验控制。

---

## 2. 首要原则：五折不是五轮主动学习

五折是五个彼此独立、从零开始的实验重复；主动学习轮次则发生在每一折内部。

```text
fold_00: reset -> round 0 -> round 1 -> ... -> final evaluation
fold_01: reset -> round 0 -> round 1 -> ... -> final evaluation
...
fold_04: reset -> round 0 -> round 1 -> ... -> final evaluation
```

每进入一个新 fold，必须重新初始化：

- 模型参数、优化器和学习率状态；
- 随机数生成器；
- 经验回放、缓存、检索索引和知识图谱的实验状态；
- 已查询集合、历史奖励和停止计数器；
- 由当前折训练数据拟合的归一化、特征选择、校准和不确定性估计器。

不得把某一折获得的候选标签、提示词记忆、模型权重、超参数调整结果或失败经验注入另一折。若使用跨折统一确定的超参数，必须在运行五折前冻结，并记录其来源；不能在看到五折测试结果后反复修改。

## 3. 统一的数据访问权限模型

建议运行器不要向 agent 直接提供完整 DataFrame，而是按能力暴露四种接口：

- `AgentView`：可见初始已观测样本及其标签、当前未查询候选的序列或突变描述；
- `ControllerView`：额外持有允许用于训练控制的验证集，但不将验证标签放入 agent 上下文；
- `OracleAPI`：仅允许查询本折 `oracle_pool` 中尚未查询的候选；
- `EvaluatorView`：仅在实验结束后读取密封测试标签并计算指标。

推荐权限矩阵如下。`✓` 表示允许，`条件` 表示只有在相应阶段或预算内允许，`—` 表示禁止。

| 数据或操作 | 完整 AL | AL 模块消融 | 随机顺序查询 | 预算匹配 one-shot | initial-only | 静态 OOD 模型 |
|---|---:|---:|---:|---:|---:|---:|
| 初始集序列与标签 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓（静态训练集） |
| 候选池序列/突变描述 | ✓ | ✓ | ✓ | ✓ | 可见但不得取标签 | 可按协议决定是否可见 |
| 候选池未查询标签 | — | — | — | — | — | — |
| 所选候选标签 | 条件：每轮查询后 | 条件：每轮查询后 | 条件：每轮查询后 | 条件：整批选择完成后 | — | — |
| 验证标签 | 仅 controller | 仅 controller | 仅 controller | 仅 controller | 仅 controller | 仅训练控制 |
| 最终测试标签 | 结束后 evaluator-only | 同左 | 同左 | 同左 | 同左 | 同左 |
| 查询最终测试集 | — | — | — | — | — | — |

候选序列是否可见与候选标签是否可见必须分开管理。闭环任务通常允许 agent 浏览候选空间的序列，但绝不允许在选择前访问其真实 fitness。

## 4. `AL96 closed-loop` 的正确使用方式

### 4.1 单折运行协议

每折按以下次序运行：

1. 加载该折 manifest，并校验数据、配置、代码版本和划分哈希；
2. 向 agent 提供固定的 96 条 `initial_observed` 及其标签；
3. 仅向 agent 提供本折 `oracle_pool` 的候选身份、序列和允许的非标签元数据；
4. 在第 `r` 轮，模型只能使用初始 96 条和第 `0...r-1` 轮已经查询返回的标签；
5. agent 提交不超过本轮 batch budget 的新候选，oracle 校验其属于本折候选池且未重复查询；
6. oracle 返回本轮所选候选的标签，更新已观测集合；
7. 达到总预算或预先冻结的停止条件后，关闭 oracle；
8. evaluator 一次性读取密封测试集，计算最终代理模型泛化指标和闭环发现指标。

第 `r` 轮开始前可用的有标签集合应严格为：

$$
L_r = L_0 \cup Q_0 \cup Q_1 \cup \cdots \cup Q_{r-1},
$$

其中 $L_0$ 是固定 96 条初始实验，$Q_i$ 是第 $i$ 轮实际查询并返回标签的集合。任何未被查询的候选都不能进入损失函数、校准器或早停统计。

### 4.2 验证集如何使用

验证集的作用应限于训练过程控制，而不是成为每轮可反复试探的隐藏 oracle。建议采用两级约束：

- 每轮训练内部优先从当前 `L_r` 中按 group-aware 方式临时划出 train/calibration 子集；
- 固定 benchmark validation 只在预先规定的少数检查点使用，例如 round 0、预算中点和最终轮，且只向 controller 返回有限指标，不返回逐样本标签或排序。

如果每轮都依据同一固定验证集选择模型、提示词、采集函数和超参数，那么验证集会被自适应过拟合。当前工程中若存在“每轮都把固定 validation 标签传给 predictor”的流程，应在实现分割模块时同步改造调用边界。

### 4.3 五折汇总

五折应使用相同的：

- 初始预算、总查询预算、每轮 batch size 和最大轮数；
- 模型训练步数或等价计算预算；
- 停止规则和候选过滤规则；
- 评价指标定义。

最终以 fold 为独立统计单位进行宏平均，并同时报告五个单折结果。不要把五折所有候选拼接后当作一个超大样本计算置信区间，否则会低估实验方差。

## 5. `FLIP-compatible static OOD` 的使用方式

### 5.1 推荐用途：静态监督学习评估

对于 `one_vs_rest`、`two_vs_rest`、`three_vs_rest` 或 `low_vs_high`，OOD 测试域由明确语义规则固定：训练域是允许看到的分布，测试域是密封的外推目标。五折主要轮换训练域内部的 validation shard，而不是把固定 OOD 测试域轮流放回训练。

静态模型按普通流程使用：

```text
train domain -> model fitting
validation shard -> model selection / early stopping
fixed OOD test -> one-time final evaluation
```

这种轨道回答“模型能否在不获得目标域标签的条件下外推”，不回答“模型通过实验反馈能多快发现高 fitness 候选”。两者不应混用同一结论。

### 5.2 若用于主动学习

若希望在 FLIP-compatible split 上运行主动学习，默认只能查询训练域内单独划出的 query pool，固定 OOD test 仍必须完全不可查询。此时研究问题变为：

> 在不测量 OOD 目标域的前提下，主动选择哪些训练域实验最有利于 OOD 泛化？

如果允许查询原固定 OOD test 中的样本，那么这些样本从首次查询起已经变成 adaptation/query 数据，不再是测试数据。需要事先另建一个互斥的、始终密封的 OOD final test，而不能继续用原测试标签报告“零样本 OOD”性能。

`low_vs_high` 的集合成员资格依赖真实 fitness，因此本身是 label-dependent benchmark。它可以作为复现 FLIP 语义的静态基准，但不应伪装成真实部署时可由序列单独构造的候选池，也不应与纯 label-blind closed-loop 结果直接合并。

## 6. `Mutation-identity OOD` 的使用方式

### 6.1 默认用途

该划分用于回答：当测试变体包含训练和验证期间完全未出现的原子突变身份时，模型能否泛化？因此，默认应作为静态 OOD 轨道使用。

对于测试身份集合 $I_{test}$，必须满足：

$$
I_{test} \cap (I_{train} \cup I_{val}) = \varnothing.
$$

被标记为 `quarantine` 的混合变体不用于训练、验证或主要测试；它们同时包含 validation-held-out 和 test-held-out 身份，若强行归入任何一侧都会模糊身份边界。

### 6.2 为什么不能直接查询测试身份

一旦主动学习查询了携带某个 test-only 突变身份的变体，该身份对模型而言就不再是 unseen mutation。后续指标只能称为 few-shot adaptation 或 online adaptation，不能再称为 mutation-identity OOD。

若研究目标确实是“学习一个新突变身份需要多少次实验”，应新增独立协议：

- `adaptation identities`：允许在预算内查询；
- `evaluation identities`：始终密封，且与 adaptation identities 互斥；
- 在每个身份内进一步分离 query combinations 和 final combinations。

这应作为单独的 cold-start adaptation benchmark，不建议在第一版三种 split 中隐式加入。

## 7. 主动学习模型与消融实验的本质差异

“消融”不是一个单一基线。应根据要回答的问题区分下列类型。

### 7.1 模块消融：仍然属于主动学习

例如移除知识图谱、LLM 推理、结构特征、不确定性估计、多样性约束或奖励塑形。此类实验仍然逐轮查询并利用反馈，因此应与完整模型使用完全相同的：

- fold manifest、初始 96 条和候选池；
- 总预算、轮数和每轮 batch size；
- oracle 接口和标签返回时间；
- 训练/重训练频率；
- 计算预算或明确报告额外开销；
- 随机种子组。

模块消融与完整 AL 的唯一预定差异应是被移除或替换的模块。若同时改变预算、特征、初始化或训练轮数，就不能把结果差异归因于该模块。

### 7.2 随机顺序查询：采集策略基线

该基线每轮从剩余候选中随机选择相同数量的样本，仍然接收每轮标签反馈并按相同频率重训练。它控制了“仅仅多获得标签”带来的提升，用于衡量智能 acquisition 相对随机实验的增益。

### 7.3 固定排序顺序查询：重排序消融

模型只在 round 0 对所有候选排序一次，之后按该固定顺序逐批查询；可以接收标签并更新预测器，但不得重新排序。它与完整 AL 的差异主要是是否根据新反馈更新采集决策，因而可隔离 adaptive re-ranking 的价值。

### 7.4 预算匹配 one-shot：顺序适应性基线

在看到任何新标签前，一次性选出总预算 $B=R\times b$ 个候选；只有整批选择锁定后才揭示标签。随后可按预先规定方式训练最终模型，但不能用新标签改变已锁定的选择。

它与完整 AL 拥有相同的新增标签数量，却没有轮间适应，适合衡量 sequential feedback 的贡献。

### 7.5 `initial-only`：无主动学习下界

该模型只使用初始 96 条，不查询任何候选。它衡量“完全不做新实验”的能力，但标签预算小于 AL，因此不是预算匹配比较。报告时应明确写成下界或零新增实验基线。

### 7.6 全监督或 oracle 上界

使用全部候选标签训练、由真实标签直接挑选候选，或在采集时访问隐藏 fitness，只能作为诊断性上界。它不属于可部署方法，也不能与 AL 的 discovery efficiency 作同等级显著性比较。

## 8. 推荐的最小消融矩阵

在每个 fold 和每个预注册 seed 上至少运行：

| 实验 | 是否逐轮反馈 | 新增标签预算 | 是否动态重排 | 主要回答的问题 |
|---|---:|---:|---:|---|
| Full AL | 是 | $B$ | 是 | 完整系统表现 |
| Random sequential | 是 | $B$ | 随机 | acquisition 是否优于随机 |
| Fixed-ranking sequential | 是 | $B$ | 否 | 动态重排是否有价值 |
| Budget-matched one-shot | 否 | $B$ | 否 | 顺序反馈是否有价值 |
| No-UQ / greedy | 是 | $B$ | 是 | 不确定性与探索的贡献 |
| No-diversity | 是 | $B$ | 是 | 批内多样性约束的贡献 |
| No-KG / No-LLM / No-structure | 是 | $B$ | 是 | 对应模块的边际贡献 |
| Initial-only | 否 | $0$ | 否 | 不做新实验的下界 |
| Full-label oracle | 不适用 | 全部 | 不适用 | 诊断性上界 |

如果计算成本有限，应优先保留 Full AL、Random sequential、Budget-matched one-shot、Initial-only 和与论文核心创新对应的一个模块消融。

## 9. 公平比较的具体控制项

### 9.1 共享不可变实验条件

同一比较组必须共享：

- 完全相同的 split manifest 哈希；
- 相同 fold、初始集合、候选池和最终测试集；
- 相同查询预算、batch size、轮数和停止规则；
- 相同候选合法性过滤与重复查询惩罚；
- 相同基础预测器、特征版本和数据预处理，除非它们正是被消融的对象；
- 相同训练资源上限和超参数冻结点。

### 9.2 配对随机性

完整 AL 与各消融应使用配对的 `(fold_id, seed)`。训练初始化、数据顺序和随机基线的采样流应从命名独立的随机流派生，避免一个组件多消耗随机数后改变其他组件的随机结果。

统计检验应基于同一 `(fold_id, seed)` 的配对差值，而不是把所有运行当成互不相关样本。

### 9.3 历史状态与提示词控制

agent 系统容易发生传统 ML benchmark 之外的泄露：

- 人工查看测试结果后修改提示词，再重跑同一测试集；
- 在全局记忆或向量库中保留其他 fold 的标签；
- 让 LLM 从文件名、排序、日志或缓存键推断隐藏标签；
- 使用上一次方法的查询轨迹为下一种方法缩小候选范围。

因此每个 run 应在干净进程或等价隔离环境中运行，日志只追加写入该 run 的命名空间。所有方法只能从同一个公开 manifest 和各自运行中真实获得的标签开始。

## 10. 指标体系

### 10.1 闭环发现指标

这些指标只依赖已查询标签或由 evaluator 在结束后对完整候选域计算：

- `best_seen@budget`：预算用尽时发现的最高 fitness；
- `AUC-best-so-far`：最佳已发现 fitness 随累计查询数变化曲线下面积；
- `simple regret`：候选域真实最优值与 `best_seen` 的差，真实最优值只能由 evaluator 读取；
- `top-p% hit rate`：是否及何时命中候选域真实 top 1%、top 0.1% 等；
- `enrichment factor@k`：前 $k$ 次实验中的高 fitness 富集；
- `unique valid queries`、重复率和非法候选率；
- `diversity@budget`：所发现高 fitness 序列的汉明、位点或结构多样性。

`best_seen` 和 `AUC-best-so-far` 应作为主要 AL 指标，因为它们直接反映有限实验预算下的发现效率。

### 10.2 最终代理模型指标

在密封 final test 上一次性计算：

- Spearman 相关；
- NDCG 或 top-k recall；
- RMSE/MAE（若不同数据集 target 尺度可比或已明确归一化）；
- 概率/区间校准指标；
- 按 mutation depth、component、position 或其他预注册亚组分层的性能。

高测试相关性不等于高发现效率，二者必须分别报告。

### 10.3 静态 OOD 指标

FLIP-compatible 和 Mutation-identity OOD 应重点报告 Spearman、NDCG、RMSE/MAE、top-tail recall，并报告每折有效训练、验证、测试和 quarantine 数量。对于固定测试域的 FLIP-compatible 五折，还应说明测试样本相同、变化来自训练域 validation 轮换，避免把五个高度相关的测试结果误当作完全独立的数据集。

### 10.4 汇总与不确定性

建议：

- 先对每个 `(fold, seed)` 计算单次指标；
- 以 fold 为一级重复，报告宏平均、标准差或 bootstrap 置信区间；
- 同时报告中位数和最差 fold，防止均值掩盖困难子域；
- 方法比较使用配对 fold/seed 差值；
- 除总体结果外，报告 HD3/HD4 或相应突变深度分层结果。

## 11. 三类 split 与主动学习的推荐关系

| Split | 默认任务范式 | 可以查询哪里 | 不得查询哪里 | 推荐主要结论 |
|---|---|---|---|---|
| AL96 closed-loop | 主动学习 | 本折 `oracle_pool` | validation、final test、quarantine、其他 fold | 有限预算发现效率与闭环建模能力 |
| FLIP-compatible static OOD | 静态 OOD | 默认不查询；AL 扩展仅查询 train-domain pool | 固定 OOD test | 低阶→高阶或低→高 fitness 外推 |
| Mutation-identity OOD | 静态身份 OOD | 默认不查询 | held-out mutation identities 及其 final test | 对未见原子突变身份的泛化 |

如果需要用后三者之一研究在线适应，应显式建立新的 `adaptation_pool` 和仍然密封的 `final_test`；不能把已经查询过的样本继续当作 OOD 测试样本。

---

## 12. 常见错误及判定规则

以下任一情况都会使主要结论失效或需要降级解释：

1. 每轮查看 final test 或依据 final test 指标选择 checkpoint；
2. 查询 OOD test 后仍声称 zero-shot OOD；
3. Mutation-identity OOD 的 held-out token 出现在 train 或 validation；
4. 完整 AL 与消融使用不同的初始集、候选池或新增标签预算；
5. one-shot 在选择尚未锁定时提前看到部分新标签；
6. 随机基线不重训练，却与逐轮重训练的完整 AL 比较并把差异全部归因于 acquisition；
7. 将 initial-only 与预算匹配 AL 当作等标签成本比较；
8. 跨 fold 保留权重、缓存、查询记录、知识图谱或人工调参经验；
9. 用真实 target 参与 label-blind split 的分层、去重保留或候选筛选；
10. 把 FLIP 的 label-dependent `low_vs_high` 结果解释为部署时无需标签即可构造的数据划分。

还应记录每次 oracle 请求的候选 ID、请求时间、返回状态和累计预算。审计程序必须能够从日志重放“模型在每轮之前究竟知道哪些标签”。

---

## 14. 最终建议

推荐将三类 split 视为互补而非互换的评价轨道：

- 用 `AL96 closed-loop` 比较 agent、多轮反馈和采集模块，主要看有限预算的发现曲线；
- 用 `FLIP-compatible static OOD` 与既有工作对齐，检验突变阶数或 fitness 区域外推；
- 用 `Mutation-identity OOD` 检验对全新突变身份的组合泛化，并严格禁止查询测试身份。

主动学习消融的核心公平性条件是：共享同一折、同一初始信息、同一候选空间、同一新增标签预算和同一反馈时间表，只改变预注册的组件。`Random sequential` 控制标签增量，`budget-matched one-shot` 控制总预算，`fixed-ranking sequential` 控制动态重排序，`initial-only` 提供零新增实验下界。这样才能分别回答“采集策略是否有效”“多轮适应是否有效”和“某个 agent 模块是否有效”。
